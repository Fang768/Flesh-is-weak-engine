## 6. 设计决策（为什么这么做）

1. **主线用 V3，Easy Mode 只作备用**：campaign 需要成长、义体、经济、装备骨架；Easy Mode 三局后角色无变化。
2. **先做「薄闸门」再做内容**：闸门是路由层、引擎是纯函数库，互不阻塞；反过来做会让每个 handler 回头补权限，漏一个就是「没人开团时乱说话烧 token」。
3. **模型只提议、程序定数值**：模型输出 `{action, skill, approach, target}`，骰点/DV/伤害全在引擎；旁白禁止改数字改成败。
4. **注意力窗口用参与者集合**：第二个人 @ 机器人是追加不是顶替，避免多人跑团互相踢出窗口。
5. **一群一主线**：`group_sessions` 单行记录，私聊与群消息都路由到当前活动主线。

**排障三件事（都真踩过）**

1. **端口占用**：重启前先 `Get-NetTCPConnection -LocalPort 8080 -State Listen | % OwningProcess`
   → `Stop-Process -Id <pid> -Force`，否则 `[Errno 10048]`。
2. **DeepSeek 400**：`response_format=json_object` 要求提示里出现 `json` 字样，
   漏了会报 `Prompt must contain the word 'json'`。`NARRATE_SYSTEM` 已加 `{"narration": …}`。
3. **生成 Python 代码不要用 `\n`**：在 Git Bash heredoc 里写 `"\\n"` 会落盘成真实换行，
   连续两次编译报错（`unterminated f-string`）。一律用 `chr(10)`。
