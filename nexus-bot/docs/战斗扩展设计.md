# 战斗模块缺口怎么补（设计）

现在 `core/combat.py` 能做到的：先攻队列（含敌人）、1 移动 + 1 动作、动作推进轮次、敌人自动回合、近战对抗闪避、远程 vs DV、瞄准 −8 与部位、装填/移动/跑/起身/延迟、HP 写回角色卡。

《歌剧院之夜》暴露的四个缺口，按「数据 → 规则 → 脚本 → 场景」四层补，不要往 `combat.py` 里硬塞 if。

---

## 一、敌人模板库（数据层）

现在敌人写死在 `ENEMY_PRESETS` 里（打手/精英/头目，8 个字段）。改成数据文件：

`rules/red/data/enemies.json`

```json
{
  "小丑": {
    "hp": 35, "wound": 18, "death_save": 4, "sp": 11,
    "stats": {"INT": 4, "REF": 7, "DEX": 4, "TECH": 7, "COOL": 6,
              "WILL": 5, "LUCK": 0, "MOVE": 6, "BODY": 4, "EMP": 1},
    "armor": "轻型装甲夹克 SP11",
    "weapons": [
      {"name": "重型手枪", "damage": "3d6", "rof": 2, "skill": "手枪"},
      {"name": "气枪", "damage": "1d6", "rof": 2, "skill": "手枪"}
    ],
    "skills": {"手枪": 12, "重武器": 12, "闪避": 9, "搏击": 9, "觉察": 10},
    "cyber": ["复眼改造", "赛博义眼x6+防眩晕+微光", "射镖枪x4"],
    "note": "声望 1；剧本《歌剧院之夜》"
  }
}
```

- `combat.load_enemy(name)` → `Combatant`，保留 `ENEMY_PRESETS` 作为兜底（打手/精英/头目仍可用）。
- 剧本里的 6 张表（爱乐吸血鬼蠢蛋 / 小丑 / 僧侣 / 审判官和尚 / 博佐帮蠢蛋 / 鲁思文勋爵）一次性录进去，以后所有本都复用。
- 炮塔单独一条：`immobile: true`、`weapon 突击步枪`、`hp 40 / sp 10`、`attack_skill 14`（书 p174 远程武器表）。

## 二、阵营（规则层）

现在只有 `side: pc / enemy`。改成三方：

| side | 谁会打它 | 它会打谁 |
|---|---|---|
| `pc` | enemy | enemy |
| `enemy` | pc、ally | pc、ally |
| `ally` | enemy | enemy |

爱乐吸血鬼是 `ally`：目标是小丑/僧侣，**被玩家攻击才还手**（这一条写在脚本里，不写死）。

`target_from_text` 与 `_enemy_turn` 都要按 side 过滤，不能再「第一个活着的」。

## 三、战斗修正（规则层）

现在没有「带时限的修正」。加一个战斗级修正表，存在 `combat.modifiers`（JSON 列）：

```json
[{"id": "scream", "value": -4, "rounds": [1, 3], "applies_to": "all",
  "negate_if": ["水平阻尼降噪"], "note": "歌剧院里的尖叫混乱声"}]
```

- `combat.modifier_for(actor, round) -> int`：遍历修正表，命中回合区间 + `applies_to` + 没被 `negate_if` 抵消就累加。
- `attack()` / 敌人回合 / `turn_flow` 的检定都乘上这个值，回复里注明「（尖叫 −4）」。
- 因为要「前 3 轮」，`round` 必须从 combat 里读，不是全局状态。

## 四、敌人行为脚本（脚本层）

敌人不能只有「随机打一个人」。最小 DSL 五个字段，够覆盖这个本：

```json
{
  "targets": {"split": ["pc", "ally"], "rounds": [1, 2], "after": "nearest"},
  "flee_if": {"round_gt": 3, "any_serious": true, "any_critical": true},
  "flee_action": "sprint",
  "on_flee_fail": {"self_destruct": {"weapon": "穿甲手榴弹", "damage": "6D6", "note": "伪装成念珠"}},
  "join_round": 1
}
```

执行点只有一个：`_enemy_turn()` 开头先问脚本

1. `join_round`：还没到就跳过（吸血鬼第 1 轮加入）
2. `flee_if`：任一条件成立 → 本回合执行「逃跑」（完整回合 + 冲刺动作）；如果 `sprint` 也跑不掉（出口被堵/移动力不够）→ 触发 `on_flee_fail`
3. `targets`：按轮次平摊目标，`after` 之后切回默认（最近的人）
4. 都没有 → 现有逻辑（打最近的敌对者）

**为什么用脚本而不是写死**：这是剧本作者的工具。以后每个本自己写 `"script"`，引擎不用改。

## 五、遭遇定义（场景层）

剧本场景加一个 `encounter` 字段，`开打` 不带参数时自动铺场：

```json
"encounter": {
  "groups": [
    {"enemy": "小丑", "count": 1, "side": "enemy", "script": "opera_clown"},
    {"enemy": "僧侣", "count": 1, "side": "enemy", "script": "opera_monk"},
    {"enemy": "爱乐吸血鬼蠢蛋", "count": "=pc", "side": "ally", "script": "opera_vamp"}
  ],
  "modifiers": [{"id": "scream", "value": -4, "rounds": [1, 3], "negate_if": ["水平阻尼降噪"]}],
  "note": "歌剧院混战"
}
```

- `count: "=pc"` 表示「与玩家数相同」（剧本原话）。
- `开打` → 有 `encounter` 就用它，没有才用玩家手打的名词。
- 战斗结束后给一条「遭遇结算」事件，写进 `events`。

## 六、落地顺序与工作量

| 步骤 | 内容 | 工作量 |
|---|---|---|
| 1 | `enemies.json` + `load_enemy()` + 6 张表录入 | 2 小时 |
| 2 | `side` 扩三方 + 目标过滤 | 2 小时 |
| 3 | `modifiers` 表 + `modifier_for()` + 三处检定接线 | 2 小时 |
| 4 | `script` 五个字段 + `_enemy_turn` 分派 | 3 小时 |
| 5 | 场景 `encounter` + `开打` 自动铺场 | 1 小时 |
| 6 | 测试：每步单独加，最后跑一遍歌剧院混战（模拟器） | 2 小时 |

合计约 1.5 天。**先做 1+5**（能铺场）→ **3**（−4 修正）→ **2**（吸血鬼不误伤）→ **4**（逃跑/自爆）。

## 七、不做的部分（明确延期）

- **网行**：炮塔的网络侧（F1–F4 黑冰、控制节点 DV8）需要一整套 Netrunning 规则，单独一期。当前用「硬打炮塔」代替。
- **爆炸物**：手榴弹 6D6 范围伤害需要格子判定，等地图接线（P2）恢复后再做。
- **敌人技能检定**（非攻击，比如僧侣的战术、小丑的拷问）：剧本没用上，先不做。
