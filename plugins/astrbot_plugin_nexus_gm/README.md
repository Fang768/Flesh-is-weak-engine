# NEXUS 0.2.8-rc1 安全暂停与恢复候选版
须配套Neon存档0.2.4-rc1。仅隔离测试，尚未安装真实环境。

## 暂停
玩家发送“暂停”或以【暂停】开头的消息，走程序直达路径，无需模型。闸门持久化到Neon数据库；NEXUS流程、可信骰点、旧Neon提案/同意/批准及资源结算均拒绝。暂停前已完成的事务和骰点保留，不回滚重掷。附带原因不写入NEXUS行动文本，也不要求说明原因。平台原始消息日志不由本插件控制。
在途模型任务会取消；即使模型忽略取消并在恢复后返回，旧控制版本仍被拒绝。暂停后的镜头不会回传。重启保留闸门；旧版已暂停会话启动时接入闸门。

## 恢复流程
1. 相关玩家或管理员/nexusresume，返回申请ID、摘要、原场景/窗口、相关角色，30分钟有效。
2. 当前参与者及暂停发起者分别本人/nexusresumeconsent ID 摘要；不会自动恢复。拒绝用/nexusresumereject ID 摘要，保持暂停，无需解释。
3. 全员同意后管理员/nexusresumeapprove ID 摘要。普通玩家不能批准，管理员不能代替他人同意。
4. 恢复只解除同一安全检查点的暂停；不改变游戏revision、角色、已行动名单、原骰点或待处理动作。恢复本身不掷骰，未掷骰动作要原玩家明确重新提交。
新的暂停、拒绝、申请过期、真实存档版本变化或检查点变化使旧申请失效。新的暂停重置恢复确认。重复同意/批准不重复执行。旧的暂停消息重投不冒充新暂停，新发【暂停】会再次锁定。

## 存档配套改动
Neon只新增暂停闸门/暂停参与者/提案控制版本表及入口校验，原store.py、templates.json和奖励/骰点公式不变。暂停恢复后旧Neon提案必须重建并重新同意，不允许顺手批准暂停前的旧提案。
双方授权与管理员恢复记录持久化；两个库不构成分布式事务，采用先保留授权、后解除闸门的可恢复协议。已模拟多个中断点；异常不应使用旧数据库覆盖。

## 超时改进
保留0.2.7有限重试及同窗口缓存；暂停会取消模型任务且不重试；恢复指令和明确的“确认结束/我确认结束本轮行动”不调用模型。语义自由行动仍用现有DeepSeek，不能保证服务延迟或消除全部超时。

## 升级
必须先确认并停机备份两库、旧代码和白名单，同时替换两个插件，保留plugin_data，不初始化、不卸载、不覆盖存档。启动会将现有显式暂停接入共享闸门，新增测试群安全审计元数据，但不改saves/revision。不要只降级Neon，否则失去共享闸门校验；加载失败保持停机排查。
当前白名单仅测试群，HOME不得加入。真实验收需玩家本人分别确认，AI不能代同意。

## 边界
仍是非战斗短任务原型，未增加完整战斗规则；原有战斗请求只转审核。固定2—3人、有监督非战斗试玩需真实恢复验收后再决定。阵容或真实revision已变化时拒绝自动恢复，须管理员核对；不暗中重排窗口。QQ送达仍无服务端回执，但控制与判定先持久化。
