## 已完成：存量卡起始资金迁移（2026-11-10）

红经济上线后，2026-11-10 之前建的卡 `state.eb` 是空的 → 一件义体都装不起。
本批补了自动迁移。

**判据是 `state.eb_granted` 标记，不是当前余额。**
用余额判断会有个致命 bug：玩家把 500 花光是合法的（余额变 0），下次启动又被判定
「没发过」再补 500 → 无限刷钱。标记一旦写上就永不再补。

| 卡的状态 | 迁移行为 |
|---|---|
| 老卡，没有 `eb_granted`，余额 0 | 补 500，写 `eb_granted=500` |
| 老卡，没有标记，但已自己挣到钱（如 800） | **不加钱**，只写 `eb_granted=800` |
| 有标记（花光了 / 已补过） | 完全不动 |
| 新建卡 | `roster.build()` 里 `init_starting_eb()` 直接发，同标记 |

**接线**：
- `growth.blank_state()` 加 `eb_granted: 0`
- `growth.init_starting_eb()` 改为按标记判断（原实现按余额，会重复发）
- 新增 `growth.migrate_starting_eb(cards)` 纯函数
- 新增 `core/runtime.migrate_starting_eb(conn)` 落库 + `run_startup_tasks()`
- `bot.py` 启动时调 `run_startup_tasks()`，**迁移失败不挡启动**（只打 stderr）

**真实库执行记录**：`data/nexus.db` 上跑通，2 张存量卡各补 500 EB
（`凯` 1376009859 / `赤尾`），重跑返回空列表 → 幂等已验证。

**测试**：`tests/test_eb_migration.py` 12 项（补一次、幂等、花光不补、自挣不覆盖、
空列表、建卡路径幂等、RED 卡落库、简易卡落库、补完真能买义体、坏库不崩、blank_state 含标记）。

## 已完成：义体实例模型重构（2026-11-10）

> 起因：旧模型把义体存成**扁平名字列表** `["赛博义眼","赛博义眼","图像增强"]`，
> 分不清配件挂在哪只眼/哪条臂上；手/腿还共用「赛博义肢」分类，会互相误挂。
> 主人拍板「需要实例级归属，最开始就应该这样做」。

### 一、新数据模型

`state.cyber`（RED 卡）或顶层 `cyber`（简易卡）现在是**实例记录**：

```json
[{"id": "c1", "name": "赛博义眼", "parent": ""},
 {"id": "c2", "name": "赛博义眼", "parent": ""},
 {"id": "c3", "name": "图像增强", "parent": "c1"}]
```

- `id`：实例唯一标识；`parent`：配件挂到哪个**基础实例**（基础组件自己为空）。
- **容量按每个基础实例单独算**：每只眼 3 槽互不共享；一只眼塞满不影响另一只。
- **旧卡自动迁移**：读入字符串列表时发 id、按分类规则推断 parent（`slots.normalize`）。
- 安装可指定父实例：`安装 图像增强 到 c1`；不指定则自动挑有空槽的那件。
- 卸载按实例 id 移除；带配件的基础组件仍会被 `uninstall_blockers` 拦住。

### 二、顺带修的真 bug

**手臂/腿配件互相误挂**：`赛博义肢` 有两个 base，旧 `_parent_base` 取「第一个已装」，
导致「只有腿也能装工具手」「只有臂也能装剃刀足」。修法：
- `cyberware_slots.json` 给 16 件手臂件补 `requires_any:["赛博手臂"]`、
  5 件腿件补 `requires_any:["赛博腿"]`；
- `_parent_base` 先看 `requires_any` 认父级，再走多 base 兜底。

## 已完成：快拆槽（快拆挂扣自带 2 个臂槽）（2026-11-10）

> 主人定案：**不做 LPTU 实体装备**（那是 CP2020 的设定），而是让快拆挂扣自身
> 带 2 个「快拆槽」——最简单，也贴合「快拆是个机械结构」的设定。

### 一、机制（ID 版，主人 2026-11-10 最终定案）

- 装上**快拆挂扣** → `state["quick_slots"] = []`（容量 2）+ `state["quick_ids"] = []`。
- **核心判定按「臂的实例 id」**，不按类型名：
  - 每条赛博臂在实例模型里有一个唯一 `id`（如 `c1`）。
  - 第一次装上某条臂时，把它的 `id` 记进 `quick_ids`，并照常扣人性。
  - 之后**换回同一条臂**（id 在 `quick_ids` 里）→ **免人性**。
  - 换一条**没有 id 记录的全新臂** → 照常扣人性，并把它的 id 记进 `quick_ids`。
- 装快拆挂扣的前提下**卸下赛博手臂** → 收进快拆槽（带 id，不卖、不退款）；槽满则照常出售。
- **战斗内「换臂」= 一个动作**（不是拆+装两个动作）：取下当前臂 + 从槽取另一条，合并为 1 个动作。
  指令：`换臂` / `换手臂`。
- 快拆挂扣是「插座」性质：拆臂时它留在身上（不拦拆臂，自动挂到另一条臂或悬空）。

### 二、为什么这堵住了「街上捡同类臂」的漏洞

判定看的是**臂的 id**，不是名字。街上捡的无主臂 id 不在你的 `quick_ids` 里 →
装它照样扣人性、并把新 id 记进去。只有真正「上过你身」的那条臂才免。

### 三、实测

```
槽里 2 条全新臂（id=new-A/new-B，不在记录）→ 换一条全新：
  🦾 装上了赛博手臂：人性 29 → 26（掉了，并把 new-A 记进 quick_ids）
槽里一条已记录 id 的臂 → 换它：
  🦾 一个动作换好了手臂（这臂 id 在记录里——免人性、不花钱）
```

### 三、改动

- `core/cyber_flow.py`：`QUICK_SLOTS = 2`；`_qr_entries`（槽条目带臂 id）、
  `_quick_ids`/`_mark_quick_id`（快拆挂扣的 ID 记录）；安装时按 id 判定豁免、
  装快拆挂扣初始化；`swap_arm()`（一个动作换臂，按 id 判定）；`status_text` 显示「快拆槽」。
- `core/combat.py`：`换臂` 指令 → 消耗 1 个动作调用 `cyber_flow.swap_arm`。
- `cyberpunk/slots.py`：`uninstall_blockers` 不把快拆挂扣算作阻拦拆卸的子件。
- 测试：`tests/test_cyber_utility.py` 17 项（含「全新臂扣人性」「已记录 id 免人性」）；

## 待办：剧本推进卡死（2026-11-13 记录，未开工）

> 起因：主人问「完整跑通剧本还差什么」。我先用假模型下了错误结论，改用真模型
> 复测后定位到真因，记录如下。

### 一、先纠正一次误判

**假模型不能用来判断「玩家能不能推进剧情」**：`scripts/simulate.py` 的
`FakeLLM._propose` 完全不读玩家的话，固定从技能池里挑「潜行」。
所以先前「卡在第一幕」的结论不可信。

### 二、真模型实测（a1.hook，gate = 说服 DV15）

| 玩家说 | 模型判 | 撞上 gate？ |
|---|---|---|
| 我接受委托，问清楚细节 | **交谈** | ❌ |
| 我想打听那七个失踪的女人 | 街头智慧 | ❌ |
| 我问他报酬怎么付 | **交谈** | ❌ |
| 我看看四周有什么 | 觉察 | ❌ |

**模型判断是合理的**：它的 `approach` 写的是「你接受委托并向对方追问失踪案的细节」，
语义完全正确。问题在于：

* **「交谈」与「说服」都是 RED 的正式技能**（`skills.json:58` 交谈 EMP / `:61` 说服 COOL），
  模型选哪个都在规则内；
* `story.gate_for()` 要求 `gate.skill == proposal.skill` **完全相等**；
* 剧本每场只写**一个** gate 技能（11 个 gate 全是单个）。

→ 同一件事有多种合规做法时，只要模型选了 gate 没写的那个，**永远撞不上**，
退回 `FALLBACK_DV`，场景不推进。

### 三、结论

**不是玩家抓不住剧情，也不是模型判断有问题，是剧本数据无法表达
「这件事可以用哪几种技能做」。**

   引擎匹配时在组内找。
2. **保留「技能不对就不推进」的硬约束**——只放宽「剧本能表达哪些技能可用」，
   不放过「数值由程序定」。

**倾向 1 做、2 不做**：语义分组应进数据，不硬编码进匹配逻辑

## 已完成：NPC 记忆 + DM 牌面 + 偏离提醒（2026-11-14）

> 主人拍板的一整套设计（对话记录见存档）。核心一句话：
> **记忆按「何时被读」分区，不按「重不重要」分区。**

### 一、三层记忆

| 层 | 表/字段 | 何时读 | 条数 |
|---|---|---|---|
| A 剧情标记 | `plot_marks` | **每次**调模型（进牌面） | 8（预算） |
| B 人际记忆 | `npc_memory.relations` | 只跟这个 NPC 有关时 | 最近 10 + 关键词补 5 |
| C 对话流水 | `npc_memory.exchanges` | 跟这个 NPC 说话 | 5（滚动丢） |
| — 印象 | `npc_memory.impression` | — | **空位**，先不写 |

**为什么分两层而不是一层**（主人原话）：

> 「玩家不是无情的推剧情工具，有一些问答的记忆是为了获取情报，可以滚动丢弃，
> 有些需要 NPC 作为一个真正的人类该记住的事情需要留下，尽管可能跟剧情无关，
> 这部分一般不作为上下文，只在玩家跟该 NPC 对话或者对话中涉及该 NPC 的时候调用。」

所以 **B 层不进牌面**——它再多也不会撑爆上下文。

### 二、旧的不删 + 关键词召回（防健忘）

B 层超过 10 条**不删**。检索时：

```
最近 10 条必给 + 更老的按 keywords 命中补召回（最多 5 条，总 ≤15）
```

关键词要求 **≥2 字**（单字会误伤正常对话，沿用 `clues.match:39` 的经验）。

剧本写法：`on_success.mark.keywords = ["委托", "莱茵迈耶"]`——
这就是「老记忆的检索索引」。

### 三、DM 牌面

```
[牌面]
  · 玩家接下了委托（a1.hook · 关键）
  · ⚠ 本场还有 1 条线索没查
```

- 只放**被标记的**剧情要点，不喂原始对话流水
- 按 `weight` 降序取前 8 条
- **「悬而未决」（⚠）是状态不是记忆，不占 8 条预算**（主人定）

### 四、态度：0–10，锁范围，只影响对话

| 值 | 档 | 心情 |
|---|---|---|
| 0–2 | 厌恶 | 带刺、能不答就不答 |
| 3–4 | 冷淡 | 敷衍 |
| 5 | 平淡 | 公事公办 |
| 6–7 | 友善 | 愿意多说 |
| 8–10 | 亲近 | 主动帮忙 |

**锁范围**（`bounds`）：敌人 `[0,5]` 怎么示好也最多平淡；中立 `[3,7]`；
剧本可写 `attitude_bounds` 覆写（模型判错时作者能纠）。

**不参与任何检定**——命中/伤害/DV 一律不看它。

**旁白只在跨档位时给**，且委婉（「雷菲尔德眉毛舒展，似乎对你的话题很感兴趣」），
不报数字、不说「好感度」。

### 五、偏离提醒（决策 D / G）

玩家做的事跟剧本无关时，DM 委婉拨回来：

* **判定空转**：没撞上场景闸门
* **连续 3 次** → 触发一次
* **本场每类一次**：内容引导（还有线索没查）/ 时间压力
* **不剧透**：只喂「场上有谁、还有什么没看过」的**存在性**信息

两个范式（主人给的）：
* 「你注意到六名学生聚集在该地区等待公共汽车……说不定这帮书呆子会知道些什么」
* 「时间已经不早了，如果再耽搁下去，演出都快要结束了」

### 三、顺带修掉的三个真 bug

1. **`exits` 是 dict 却被当字符串用**（`turn.py`）：官方模组写法是
