## 0. 贴近真实跑团的总原则

- 每个场景有明确目标、可查信息、阻力与后果；失败推进剧情，不把门锁死。
- 战斗外也有资源压力：时间、钱、人情、声誉；休整不是无成本。
- NPC 有立场、记忆和所属组织；同一句话对不同人效果不同。
- 结算发生在 session/结局边界：EB、IP、人情、声誉一次结清，可审计。
- 引擎管硬账（谁欠谁、多少钱、用没用过），DM 的判断管裁量（认不认、够不够、后果），DM 不直接改状态。

## 1. DM 判断怎么融进每个玩法（设计约束，不单列模块）

不做独立的 `core/dm.py`，也不把「DM 判断」当成一个先做完的地基。跑团不是跟引擎做数据交换，所以**每个玩法在开发时都要同时设计四段**：

1. **玩家可以怎么说**：自由输入（“小丑欠我人情，让他开门”“我躲到吧台后面”“我想临时找条网线接进去”），不是只有固定命令。
2. **引擎先算什么**：账本里有没有这笔人情、当前场景/地图/战斗状态、该走哪个技能与 DV、动作槽够不够。
3. **DM 补什么**：这个人认不认账、这笔人情够不够、临时动作可不可行、失败了怎么演、NPC 用什么态度接。DM 的判断发生在现有 `turn_flow` 的自然语言链路里，与旁白同一次调用或紧接着的一次调用，不另开一道闸门。
4. **失败怎么推进**：裁量失败/模型挂掉时走确定性回退（严格按账本、按战斗规则），剧情继续，不卡回合。

这套判定不分战斗内外：**同一条输入门在两种模式下复用**。战斗内多查动作槽、先攻、距离、掩体与当前行动者；非战斗多查时间、场面、人情与后果。问规则/问路/闲聊这类信息输入直接回答，不进入可行性确认；只有“我要做某事”才走可行性判定。
落到具体功能：

- **人情**：引擎先查 `holder/scope/used`，再由 DM 判断“认不认、要不要加价/翻脸”；引擎只执行“扣账/不扣账”，DM 不能凭空造账。
- **逃跑**：引擎跑 `flee_if`，DM 接“出口堵没堵”（替代现在写死的 `flee_blocked`）；没有 DM 时默认按脚本硬判。
- **临场动作**：玩家说“我踢翻桌子挡子弹”，引擎把它映射到最近的技能/动作与消耗，DM 决定叙事后果，伤害/状态仍由引擎结算。
- **地图**：玩家说“我躲到吧台后面”，引擎先找移动力内最近的掩体；找不到或超移动力时不静默改写，而是进入确认层：说明最近掩体在哪、差多少、要花什么代价，再问“继续找掩体 / 改躲到桌子后 / 换别的动作”。
- **场景**：每个场景可写 `dm_notes`（哪些能临场发挥、哪些是硬事实、失败代价），DM 有边界才不会把剧情改飞。
- **审计与回退**：DM 的判断记进 `events`，但不直接写角色卡/战斗状态；超时、非法、超预算一律走严格回退。

### 确认层：不可行或离谱的命令不静默改写

任何自由输入先过一遍可行性判定，结果只有三类：

- **可行**：直接执行。
- **勉强可行 / 有代价**：说明代价（多花动作、暴露、欠人情、白费回合），问“确认要这么做吗”。
- **不可行 / 过于离谱**：说明为什么不行（超移动力、没有目标、规则不支持、场景里没有这个东西），给出 1–2 个可执行替代，再问“还是要试一下吗”。确认后若确实没有现实路径，就按失败结算（白费动作/引来反应），不凭空成功。

确认提示必须带上：原因 + 代价/后果 + 替代选项。玩家回“确认/继续/是”才执行，回“算了/换”则取消；pending 确认只保留最近一条，超时或玩家直接发新命令即作废并提示。
DM 只能补代价和叙事，不能把“不可行”改成“成功”；引擎的硬判定（移动力、账本、动作槽、DV）不会因为一句“确认”被绕过。

验收时每个功能至少要有：一个自由输入的用例、一个 DM 裁量点、一个“模型不可用”的严格回退用例，外加一个“不可行命令 → 说明原因 + 请求确认 → 取消或带代价执行”的用例。

## 2. EB 与人情账本（细化）

**规则口径**：Giri 是叙事性欠条，记“谁欠你”；个人人情只对本人，组织人情才在组织内可用；不自动扩展到同帮派其他人，跨人兑现要 GM 裁定。

**数据结构**（角色卡 `state`，RED 卡与简易卡同构）：

```json
{
  "eb": 2000,
  "favors": [
    {
      "id": "f-001",
      "holder": "npc:clown",
      "holder_name": "小丑",
      "scope": "person",
      "org": "博佐帮",
      "weight": 1,
      "source_scene": "a1.opera",
      "note": "放他一条命",
      "used": false,
      "used_at": null
    }
  ],
  "settled": ["1:a3.ending"]
}
```

- `scope`: `person` | `org`；组织人情记 `holder: "org:bozo"`。
- NPC 数据（`story/*.json` 的 npcs，必要时 enemies）加 `affiliations: ["博佐帮"]`、`rank`；引擎只做显式匹配。
- 匹配规则：
  - person → 只对 `holder` 本人；
  - org → 对 `affiliations` 含该组织且 `rank` 够格的人；
  - 不自动模糊匹配；DM 可以“提议”跨级认账，但引擎要求账本里已有组织级记录或 GM 显式标记，否则拒绝。
- API：`grant_eb`、`grant_favor`、`use_favor(card, target, *, dm)`、`favors_for(card, target)`；`favors_left` 兼容现有 perk 自带人情。
- 命令：`/人情`（列出可用与已用）、`/用人情 <对象> [理由]`；流程 = 引擎校验 → DM 判断认不认/够不够 → 扣账/部分兑现/被拒，写事件。
- 账本里没有这笔人情时，明确说“账上没有这笔”，再给替代（换用别的欠条 / 当场欠新债 / 放弃）并等确认；不能自动当成成功，也不能静默换个人情。
- 奖励数据化：`story/opera.json` 的 `a1.students` 定金 500 EB、`a3.ending` 尾款 1500 EB + 爱乐吸血鬼青睐 + 4 IP；`settle` 以 `campaign_id:scene` 幂等。
- 展示：`render_state` 显示「EB · 可用人情」。
- 测试：个人人情不能给同帮派同事用；组织人情可以；重复使用被拒；DM 拒绝时不扣账；结局重复进入不重复发钱；模型挂掉走 strict。

## 3. 幸存者跨战斗二次遭遇（已完成 2026-11-07）

- 新表 `campaign_actors`：`campaign_id, actor_id, name, kind, status, hp, max_hp, scene, side, preset, fate, withdraw_at, script, data, updated_at`，主键 `(campaign_id, actor_id)`；`combat.end()` 删除 combatants 之前把带 `actor` 的非玩家参战者 upsert 进去。
- 演员表按 campaign 存，跨战斗、跨场景都在；旧剧本不写 `actor` 就不归档，行为不变。
- encounter group 支持 `{"ref": "russwin", "fresh": true, "if": "escaped"}`：`ref` 从演员表取回，`fresh` 满血回归，`if` 可按 dead/escaped 过滤；`if` 也支持 `{"escaped": [...], "not_escaped": [...]}`，`count` 支持 `=pc`、`=pc-2`、`=(pc-2)//2` 等表达式。a3.entry 已按 `playbook_opera.txt:94` 接成「幸存者 ref + PC−2 蠢蛋」，都没逃掉则跳过遭遇。
- Boss 命格：`fate: "cannot_die"`（HP 归零→escaped、1 HP 退场）、`withdraw_at`（HP 降到阈值→escaped 退场）；`_aftermath()` 区分 `on_win`（全 dead）与 `on_withdraw`（有人 escaped/withdrawn），避免“打跑 Boss”误触胜利。
- 过场 `presence`：场景可写字符串或 `{name, line, untouchable}`；untouchable 被攻击时走统一确认层，说明原因 + 给替代，回「确认」后按落空结算，不凭空成功。

## 4. 黑冰 / 接入点 / 控制节点（阶段 3，已完成）

- `encounter.net`：`access`（name/dv/skill/keywords）+ `nodes`（id/name/dv/skill/keywords/effect/ice）；`combats.net` JSON 列按 `owner_qq` 存 `connected` / `controlled` / `flags`，跨回合与 `load` 保留。
- `combat.net_action()`：先「接入」→ 成功后「黑入 <节点>」，两段都是 d10 + TECH + 技能 + 重伤 + 环境修正 vs DV；未接入时点节点名会提示先找接入点；已控节点不重复掷、不重复扣动作。
- 效果首批支持 `stop_turrets`（按 target 名字停 count 个，hp=0/dead）、`open_door`、`flag`（写 `combats.net["flags"]`）；失败时若节点有 `ice`，先做一次黑冰反扑：`ATK + 1d10 vs 你的交互界面 + 1d10`（交互界面用电子/安全技术等级代理），命中才烧 `ice.damage`（护甲不减），没命中就只是白费动作。这是中间态；完整 PER/SPD/REZ/先攻/扫除留到网行扩展。
- 旧 `encounter.hack` 保留为单节点简化版；`turn_flow` 先走 `net_action`，返回 None 再回退 `hack`，老剧本行为不变。
- `a3.church` 已配：接入接线盒 DV8 → 黑入炮塔控制节点 DV8 停 2 座；控制失败触发黑冰反扑（ATK6），命中烧 2D6。
- 测试 `tests/test_net.py` 6 项 + `test_opera_run.py` 改为接入→控制；全量 **309 passed**；simulate 新增 `net` 场景（未接入/接入/控制/黑冰反扑命中与落空），**20/20**。

### 延期：完整网行（含真黑冰）

规则书里黑冰不是独立玩法，属于**网行（netrunning）**：交互界面、接入点、网行动作、控制节点、黑冰面板与遭遇是同一套流程。当前只做了「接入 → 控制节点 + 中间态黑冰反扑」的最小闭环。完整网行整体挂起，等剧本真正需要时再一起做，不拆成独立排期：

- 交互界面等级决定每回合 2/3/4/5 个网行动作；接入点 6 米内且无墙阻隔，离开范围自动脱出并吃所有未扫除的黑冰效果。
- 黑冰三类（反人员/反程序/使魔）、面板 PER/SPD/ATK/DEF/REZ、遭遇先攻、每回合攻击、REZ 归零/遁走/扫除。
- 多程序并行、接入点控制连接物、脱出后失去节点控制等。

现阶段保留现有 `encounter.net` 数据与中间态逻辑即可，旧剧本不受影响。

## 5. 四张地图（已完成，2026-11-07）

> 落地：`maps/` 四张图 + `combats.map/covers` + `combatants.x/y`、`start()` 按 spawns 自动落位、攻击距离 DV/LOS/打掩体、战斗移动（坐标/掩体后）、自爆 5×5、`/地图`。测试 `tests/test_map_combat.py` 8 项。
> 阶段 6 追加：非战斗坐标写角色卡 `state.pos`，战斗/非战斗移动统一按 `MOVE×2` 米（`scene_move`），`tests/test_scene_move.py` 6 项；当前全量 328 passed / simulate 23/23。
> 未接：`range_m` 与 DM 估米数/动态任务 DV、通用手榴弹范围、掩体打烂后的通行/视线细化。

- 地图是**场景级**的，不是战斗专属：规则书（167 页）明确「棋盘就是想象力，网格图只是复杂情境的视觉辅助」。没有战斗时，同一张图用来回答「我在哪、能摸到什么、离吧台多远」，不进入先攻/动作槽；「走到吧台后面」这类移动直接按 `map.move()` 改位置，不扣移动动作。非战斗技能检定仍用场景 gate 的 DV（觉察 13、说服 15…），不套用武器距离 DV。
- 阶段 6 实现：非战斗坐标存角色卡 `state.pos = {"map","x","y","goal"?}`；`combat.scene_move()` 按 `MOVE` 格预算走，超出停在半路并允许「继续走」；`turn_flow.handle` 在 NPC/模型前拦截；`map_text` 非战斗时从卡里渲染 `@/A`。战斗移动也改为按卡 `MOVE`（缺省 6），不再写死 6 格。
- 照 `docs/待办缺口.md` 的 P2 六步：`combatants.x/y`、`combats.map`、按 `spawns` 落位、LOS、距离 DV、移动动作、掩体耐久。
- 距离统一用**米**存，单位就是米（1 格 = 2 米）：场景/encounter 写 `range_m` 数字，例如 `"range_m": 10`。引擎按武器距离表把米数换成 DV（手枪 0–6 米 DV13、7–12 米 DV15、13–25 米 DV20……；不同武器表不同）。「近/远/街对面/房间另一头」这类描述由 DM/LLM 说，不写进数据，剧本换算只需要填一个米数。
- **没有「无地图」，只有「无地图数据」**（2026-11-07 修订，原「15 米兜底」已废除）：距离优先级 ① 用 `range_m`；② 由 DM 根据场景描述和玩家动作估一个米数（输出 `{meters, reason}`，一次给全员填同一段距离，校验 1–800 米并映射 DV，记录在战斗日志）；③ 玩家/ DM 明说米数（`combat.close_range`，「距离 20 米」不消耗动作）；④ 都没有**不猜 DV**，回 `combat.RANGE_ASK` 请人给距离。敌人回合同一口径：无距离只「压过来」，不按默认 DV 结算。
- 非战斗任务 DV 动态化：场景 gate 给基准 DV，DM 按任务难度、工具、时间压力、环境给 ±2 调整（最终 9–29），必须带理由并记录；模型不可用时用 gate 基准。武器距离 DV 由米数硬算，DM 只能另外给环境修正（光照/烟雾等 ±2），不能改基础距离档。
- 四张图：a1.opera 观众席/舞台、a3.entry 教堂门口、a3.church 中殿/炮塔位、a3.boss 祭坛/墓室。
- 顺手接爆炸 5×5 格（设计文档 §7 延期项）；有图按中心格半径 2 结算，无图仍按同场全体并注明。
- 风险最大：命中/DV 文本回归；单独一轮，先跑无图回退再开图。
